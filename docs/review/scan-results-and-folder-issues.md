# Scan results and folder issue review

The maintainer requested compact results and both arrow navigation and immediate
shortcuts. The human-only folder predicate requires absent observation, native
name, relative candidate path, asset and receipt identities plus an explicit
Root-subject scan.root_unreadable finding. Malformed actual candidates remain
skills needing review. Name-to-observation resolution and canonical reports do
not use the human-only filter.

Folder guidance uses compiled source tiers, compiled standard location hints and
escaped logical IDs for other locations. It does not
infer permissions as the cause or expose private absolute paths. The Mac's /etc
link can make an administrator-root check unavailable under the existing no-follow
rule, independently of readable personal skills. No core root/policy repair is
part of this presentation change. A displayed error is not an adoption target.

Navigation is scan-only. All collection, initialization, trust, materialization
and sync gates use their original implementation. Queued input is discarded at
the navigation boundary and again before subsequent prompts. Raw terminal mode
is held by the existing restoration guard; only bounded Escape continuation
reads temporarily change its VMIN/VTIME. Windows console handling is unchanged.
No dependency, permission, credential or signing implementation change.

Review the final source/callers, non-mutating reports, retained selection/final
retry status, terminal restoration, unsupported/fragmented escape handling and
fresh source confirmation tests before committing. Required full stable and
Rust1.89 canonical checks, advisory and secret results are recorded in change
evidence. Manual review is not an independent-agent or exhaustive repository audit.
Publication and website deployment require separate release authority. Other
readiness monitoring and the user's installed copy and sync remain untouched.
