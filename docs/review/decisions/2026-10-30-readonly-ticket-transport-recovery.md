# Read-only ticket transport recovery review

Scope: approved narrow source repair after the merged private ownership boundary.
This is manual full-source/caller review, not independent-agent or exhaustive
repository review. Keep signing/releases and readiness monitoring off.

## Boundary and evidence

The observed final validation68/-1005 followed accepted notarization, successful
attachment and earlier native/signature checks. Recovery addresses that read-only
connection loss, not the unknown cause of every earlier attachment failure.
ADR-0070 constrains max3 calls and1s/2s backoffs inside the same deadline/retained
baseline, with the original20s cleanup reserve inside—not added afterward.

The operational native entry supplies only the already reviewed fixed validate-v
command and closed environment. Its callback/test seam is private, not an arbitrary
execution API. Every real result consumes the opaque confirmed cleanup proof;
errors or unknown ownership cannot become a later attempt. The same retained
handle/name/bytes spans all attempts/backoffs; no recapture after a successful child.
Shared cleanup duration is one constant with the unchanged value. A reaped signal
records actual confirmed cleanup but remains denied, never native0 or retryable.

Only exact native68 with complete bounded -1005/connection-lost evidence is
retryable. Unknown NSError/status syntax poisons classification instead of being
silently dropped. HTTP, mixed TLS codes, denial, missing-ticket, timeout, launch,
termination, uncertain cleanup and excessive output stop. Closed V2 records retain
the first failure, source/ARM/image binding, window, ordered attempts and backoffs.
Shared golden data plus hostile parser cases bind Rust output to the Python reader.

## Caller review

Fresh ARM source-bound preparation and final verifier use the owned recovery path.
Unbound standalone and existing Intel inputs remain single-attempt. Diagnostic
source binding reuses its strict existing context, not a new authority marker.
No environment policy, workflow, secret, profile/account, signing or dispatch
permission changes. Signing, notarization/wait and staple calls stay single-pass.

The final controller emits only a closed trace, refuses any failed recovery, then
delegates to the original strict signature check. All surrounding image, archive,
payload, provenance and source checks remain. Python requires full verifier0 AND
a fully validated V2 record bound to the copied image hash; ticket-phase success
cannot promote a failed complete verifier. Ordinary preparation forwards closed
V2 attempts on success and ordinary failure. Unknown cleanup still stops before
forwarding/observer/evidence promotion under ADR-0069.

The explicit router leaves V1 historical inspection strict, and fresh diagnostics
require V2 validation. Preparation is one V1 attachment followed by one V2 trace;
final verification is one V2 trace. Downgraded, mixed, duplicate, reordered or unknown
versions refuse. The V2 parser is lazily imported at that bridge to avoid a circular
constant import. No raw provider or exception text is promoted to result JSON.

## Verification record

Retained red/green proofs cover missing routing, lost ordinary-preparation evidence,
strict-signature delegation, expected-image/refused-record/downgrade refusal,
retained-byte mutation after actual harmless native0, and signalled child cleanup
classification. Original fixture compile/path mistakes are retained separately and
are not counted as behavioural red proofs. No guard remains disabled. Harmless
children use fixed shell/true fixtures on synthetic text, not a real image or Apple
request. POSIX copy/ownership tests keep explicit platform declarations; pure
policy and wire tests remain portable.

Pre-commit review reproduced impossible V2 timing records accepted by the reporting
parser: a zero window, a later attempt without cleanup reserve and a requested
backoff that could not fit. The real owned loop already refuses these before
execution; no native acceptance bypass was demonstrated. Producer and consumer
now reject such records too, with retained synthetic red/green proof. Python's
millisecond checks allow only the fractional margin lost by flooring; the producer
retains strict nanosecond bounds. No runtime budget changes. The initial full pair
is retained as superseded evidence, not final-tree validation.

Final full stable/Rust1.88, fresh audit/licenses/notices/governance/secret scans,
exact public required/full-platform checks and green main remain required before
acceptance. Cargo.lock, dependencies, workflow permissions, version/catalog and
release targets are unchanged. No provider/fresh-install/production acceptance,
Intel-removal implementation, automatic live follow-up or release is claimed.
