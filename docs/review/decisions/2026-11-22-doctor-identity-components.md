# Doctor recorded identity components

The affected-Mac RC5.20 report names recorded-identity mismatch in both retained
roots, but it cannot distinguish the device and file components. Released-binary
synthetic tests show either component alone can yield the same preview followed
by apply.batch_storage_failed. This establishes a sufficient current refusal,
not the affected Mac's historical cause or a safe recovery action.

Carry a closed optional identity_component from the existing Unix complete
identity inequality into StorageDoctorCleanupDetail. Keep reason identity_mismatch,
coarse errors, validation order, complete equality, no-follow opens, budget charges
and mutation behavior. No second listing/stat or external process supplies the
component. Other failure predicates and complete Windows identities leave it
absent. The public doctor JSON becomes schema3; unrelated JSON is unchanged.
Normal human output names the differing component and the other match, or both
differences. No raw identities, filenames, paths, bodies or error strings appear.

Synthetic CLI tests prove a healthy baseline, then device/file/both mismatches
for regular files, removed directories and interrupted batches in collection and
private-state roots. Verify human/JSON parity, redaction and no filesystem writes
or lock creation. Core tests retain full snapshot/native ACL protection, unchanged
coarse outcomes and budgets; Windows tests require no invented component detail.

This source change does not repair retained state, loosen identity checks, prove
restart/migration history, alter storage formats, dependencies, trust, receipts,
sync, versions or permissions, or authorize signing/publication. A disk-only
mismatch must not become an inode-only cleanup fallback. Retain current data
until evidence supports a separately reviewed recovery approach.

Validation and publication status belong in the evidence record. This note
claims neither unrun checks nor independent/exhaustive repository review.
