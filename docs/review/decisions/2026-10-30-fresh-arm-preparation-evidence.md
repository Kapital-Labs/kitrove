## Security and implementation

Follow actual Rust preparation call through Python credential wrapper and final
diagnostic. Verbose output only in exact manual/main/attempt-one/ARM/source-marked
diagnostic context; retain raw output only in memory. A closed parser emits fixed
observations, known domains/numeric errors, HTTP statuses, native exit and timing.
Python refuses extra fields, duplicate keys/operations, unexpected order, source/
target mismatch, unknown messages and excessive records. A primary nonzero result
still fails, and evidence is eligible only after confirmed Keychain cleanup.
Cancellation/process uncertainty never makes image evidence uploadable.

Manual review also identified discarded details in the existing post-cleanup
ticket and final container validation. Preserve these as separate closed records
without adding another native call. The final verifier may emit only one actual
validation record; never accept attachment or signing evidence in that phase.
Stop final checks immediately on failed direct signature/ticket control. All
checks still run and must pass on a successful diagnostic.

No raw provider/account/path echo, credentials in artifacts, token transfer, OIDC,
new permission, signing backend, attachment retry, new notary submission beyond
this single normal diagnostic preparation, firewall/TLS/trust workaround or runtime
product execution. Existing archive, notices, signature/team, ticket and payload
checks remain required. Final diagnostic success additionally requires both actual
preparation ticket records, in order, with successful exits and bounded evidence.

## Verification plan and limits

Behavioral red/green tests: exact diagnostic context and rerun/Intel/source refusal;
closed Rust domain/status parser with secret canaries and oversized output;
Python bridge invalid/duplicate/unbound records and ordering; actual native-wrapper
failure remains failure after evidence forwarding. Existing cleanup/cancellation/
image identity tests remain. Full stable/Rust1.88, manual complete source/caller
review, fresh audit/notices/governance/secret scan and exact public PR checks are
required before commit/merge. Exact green latest main precedes live execution.

This is a manual source review, not an independent-agent or exhaustive repository
sign-off. Historical native68 root cause remains unknown; previous same-byte ticket
attachment successes disprove neither a fresh-ticket issue nor transient failure.
New success establishes one successful invocation only. Preserve any actual error
without labelling HTTP3/network/propagation as proven. No further attempt follows
automatically; diagnostic artifacts are never production release authority.
