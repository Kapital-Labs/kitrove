# Kitrove 0.1.0-rc.5.6

An evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Never bypass installer ownership or recovery refusals. Intel Macs remain unsupported.

RC5.5 is the preceding successful public preview and stays immutable. All older
failed RC5 attempts also stay immutable. Existing RC4.2 APT/RPM packages and the
separate RC4.2 WinGet submission are not RC5.6 distribution paths. Cloud-provider sync
remains roadmap work only.

## Faster guided skill collection

In `kitrove init` or `kitrove configure`, choose skill collection:

- Enter previews the recommended eligible set without writing it.
- `1,4,7` selects only those numbered observations.
- `all,-3,-8` or `-3,-8` selects everything except entries 3 and 8.
- `v` shows the full inventory; `n` skips; `q` stops setup.
- After preview, `y` or `yes` approves only the displayed ready set.
  Enter does not approve bulk writes.
- `r` reviews individually: Enter/y accepts the current shown plan, n skips,
  and r renames before a new preview. Other write confirmations still skip on Enter.

Numbers refer to one retained scan, not names across tools. The preview shows
source tool and scope, collection name, four-tool fidelity and loss reasons.
Invalid/occupied names, same-name ambiguities and blocked plans are omitted.
No tool silently wins a collision. Choose one numbered source or rename explicitly.

Bulk adoption is sequential, not atomic: each item freshly replans and checks its
exact approval. A changed source, changed collection, pending recovery or failed
commit stops later items. Completed items remain and are reported. Original/native
source bytes are preserved. Adoption does not execute content, grant trust, Apply
to another tool, or sync; those actions retain separate plans and confirmation.
Credentials, machine identity, trust and deployment receipts remain local.

See the [versioned quick collection guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.6/docs/SETUP-QUICK-ADOPTION.md)
for details. This preview also contains the previously reviewed RC5.5 features,
recovery and distribution safeguards. No dependency resolution, signature,
notarization, ticket, process cleanup or publication gate is relaxed.

## Verify downloads before execution

Select the exact CLI or installer archive for your platform from this release.
The Apple Silicon installer DMG is a separate container. Adjacent SHA-256 files
and the combined checksum check integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's
full source commit. Compare it with the source commit recorded below. Substitute
the full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.6 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.6/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. A downloaded
verifier cannot establish trust in its own first execution; use an independently
trusted or reviewed-source-built verifier. Do not pipe downloads into shells,
remove quarantine, disable Gatekeeper or bypass provenance checks. Generated
convenience scripts are not the authenticated bootstrap procedure.

## Acceptance limits

Source validation and synthetic setup tests do not establish production-artifact
acceptance, every asset kind, live-harness behavior, cloud/Git-provider support,
concurrent-writer safety in every environment, Intel execution, or clean-Mac
online/offline first launch. Candidate-specific artifact verification is recorded
separately after publication. Native Windows signing does not guarantee immediate
SmartScreen reputation. The repository-wide review was risk-prioritized, not
exhaustive assurance that all defects are absent.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new)
without posting credentials or private capability content in public issues.
