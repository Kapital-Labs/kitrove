# Kitrove 0.1.0-rc.5.12

An evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. Earlier tags and release assets remain unchanged.
Existing RC4.2 APT/RPM packages and the separate WinGet submission do not
distribute this preview.

## Guided Git setup

Guided sharing can now proceed from the HTTPS username prompt to the hidden
access-token prompt. A blank username or token cancels authentication.

When sharing a collection through Git, choose `c` at the repository URL prompt
for instructions to create an empty private repository on your Git host. Then
paste its clone URL. Review and approve the synchronization plan separately.

## Verify downloads before execution

Choose the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum establish integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's
full source commit. Compare it with the source commit recorded below. Substitute
that full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.12 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.12/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. Use an
independently trusted or reviewed-source-built verifier. Do not pipe downloads
into shells, remove quarantine, disable Gatekeeper, or bypass provenance checks.

Source checks and disposable setup tests do not establish clean-Mac offline
first launch, live-harness parity, or recovery of an existing interrupted sync.
Native Windows signing does not guarantee immediate SmartScreen reputation.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
