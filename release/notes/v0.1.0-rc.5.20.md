# Kitrove 0.1.0-rc.5.20

Evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. Earlier tags and release assets remain unchanged.
Existing RC4.2 APT/RPM packages and the separate WinGet submission do not
distribute this preview.

## Changes since RC5.19

- Doctor names the first failed retained-cleanup check directly in its normal
  output: recorded identity mismatches, changed entries, links, unexpected file
  types, link-count refusals, pending batch contents, conflicting batches,
  directory protection, unreadable metadata/listings and inspection limits.
- A redacted item number identifies its position in this inspection's bounded
  sorted top-level list. It is not a filename, stable identifier or deletion
  authority. Descendant findings identify a problem inside that retained item.
- The redacted doctor JSON report advances to schema 2 with closed diagnostic
  detail. Existing role, stage, status, code and count fields remain; the report
  still says inspection is unlocked and mutation access is not tested.
- Preserve existing mutation errors, inspection ordering, ownership, identity,
  trust, cleanup budgets and no-follow checks. Native Windows regression fixtures
  prove their protection preconditions before testing a link-count refusal.

Doctor is read-only. It does not acquire mutation locks, test writes, read private
state/recovery bodies, repair permissions, initialize, recover, delete, sync,
launch tools or contact a provider. Keep retained files in place for review.
These findings do not establish a past failure's cause or guarantee a later write.
The reported batch failure on another Mac remains undiagnosed until current
observations are reviewed; this release does not claim to repair that state.
No dependency, persistence, permission or package-channel update is included.
The existing chrono maintenance notice remains disclosed without a warning ignore
or exhaustive security assurance. Fresh source and artifact checks remain gates.

## Verify downloads before execution

Choose the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum establish integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's
full source commit. Compare it with the source commit recorded below. Substitute
that full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.20 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.20/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. Use an
independently trusted or reviewed-source-built verifier. Do not pipe downloads
into shells, remove quarantine, disable Gatekeeper, or bypass provenance checks.

Source checks and disposable setup tests do not establish clean-Mac offline
first launch, live-harness parity, or recovery of an existing interrupted sync.
Native Windows signing does not guarantee immediate SmartScreen reputation.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
