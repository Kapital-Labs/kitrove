# Kitrove 0.1.0-rc.5.19

Evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. Earlier tags and release assets remain unchanged.
Existing RC4.2 APT/RPM packages and the separate WinGet submission do not
distribute this preview.

## Changes since RC5.18

- Add `kitrove doctor` for a short read-only report and closed, redacted `--json`
  output. It checks portable integrity and local storage metadata, including
  private protection, machine-local state-file metadata, existing locks,
  transaction-marker presence and retained cleanup structure. It does not parse
  private state or recovery bodies, acquire locks, test writes, normalize
  permissions, initialize, recover, clean up, sync or contact a provider.
- Default doctor inspection to `~/Kitrove`, with `--environment` for another
  collection. Reports omit paths, identities, skill names, private values and
  raw operating-system errors. An observed refusal or incomplete check needs
  review; it is not a prediction that an approved mutation cannot proceed.
- Show one compact row per saved item and a summary for the current page.
  `review N` opens separate exact local script approval, `compare N` compares
  complete bundle identity without taking ownership, and `why N` shows the
  selected description and destination or compatibility reasons.
- Keep `ready` and `all` distinct. `ready` checks matching pages when selected;
  `all` retains blocked members, so a blocker can stop the complete selection.
  Existing unmanaged copies remain unmanaged even when contents match. File
  placement still requires a fresh full preview and separate confirmation.
- Identify batch-storage boundaries with static, redacted failure messages.
  Human guidance points to doctor with the same collection selection. Existing
  error codes, code-only JSON errors, trust, ownership, recovery and transaction
  boundaries remain unchanged.
- Isolate executable test-fixture writers across processes for native CI.
  This changes test preparation, not production execution or timeout policy.
- Select heapless 0.9.4 through the reviewed tracked faster-hex 0.10.1 compatibility
  override. The override preserves faster-hex's upstream Rust sources; notice material
  includes the required upstream and nested license attributions. The scoped
  dependency review is not a claim about every upstream feature combination.

The batch-storage failure reported on another Mac has not been diagnosed by
these changes. Doctor reports current observations; it cannot establish a past
cause or guarantee that a later apply will succeed. Keep retained transaction
files in place for review. Fresh canonical, native-platform, advisory and
artifact verification remain release gates. No warning ignore is introduced;
this is not an exhaustive security assurance.

## Verify downloads before execution

Choose the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum establish integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's
full source commit. Compare it with the source commit recorded below. Substitute
that full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.19 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.19/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. Use an
independently trusted or reviewed-source-built verifier. Do not pipe downloads
into shells, remove quarantine, disable Gatekeeper, or bypass provenance checks.

Source checks and disposable setup tests do not establish clean-Mac offline
first launch, live-harness parity, or recovery of an existing interrupted sync.
Native Windows signing does not guarantee immediate SmartScreen reputation.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
