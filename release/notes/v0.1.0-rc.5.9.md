# Kitrove 0.1.0-rc.5.9

An evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. RC5.8 and all earlier tags/assets stay immutable.
Existing RC4.2 APT/RPM packages and the separate WinGet submission are not RC5.9
distribution paths. Cloud-provider sync remains roadmap work only.

## Fewer setup keystrokes, clearer Git selection

Numbered menus accept one valid key immediately on an interactive terminal;
Enter accepts the displayed default. Paths, names and multi-item source selection
remain line-based. Adoption shows a nonempty ready preview before Enter or `y`
can accept it. Choose again, individual review, skipped details, skip and quit
remain separate choices. Input typed ahead cannot approve a later unseen preview.
An empty preview never offers adoption or reports zero-item success.

Sharing now offers one Git repository choice. An explicit `https://` or `ssh://`
URL selects its transport; omit the scheme to choose it separately. The remote
repository must already exist, though it may be empty. Kitrove does not create
repositories or discover remotes from the current project. SSH still requires an
explicit existing known-hosts file and the existing agent/host verification policy.
Local checkout paths and unsupported addresses are not silently rewritten.

Each adoption still freshly checks its exact plan, source and collection state.
Failure stops later items and reports completed work. Adoption does not apply or
execute skills, grant trust or sync. Initialization, trust, Apply and sync keep
their separate approval boundaries. Credentials, identity, trust and receipts stay
local; native copies, fidelity and loss details remain preserved and visible.

## Large-collection synchronization correction

Retained-base verification now checks the collection's exact expected inventory
instead of applying a per-skill directory ceiling to the entire collection.
Unknown entries, changed payloads, unsafe paths and existing budget violations
still refuse. Disposable tests cover first publication and interrupted retained-
base recovery without a second publication. These tests do not migrate an older
collection or authorize automatic recovery of an existing user's transaction.

## Verify downloads before execution

Choose the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum establish integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's full
source commit. Compare it with the source commit recorded below. Substitute that
full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.9 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.9/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. A downloaded
verifier cannot establish trust in its own first execution; use an independently
trusted or reviewed-source-built verifier. Do not pipe downloads into shells,
remove quarantine, disable Gatekeeper or bypass provenance checks. Generated
convenience scripts are not the authenticated bootstrap procedure.

## Acceptance limits

Source validation, synthetic setup/recovery tests and unsigned local smokes are
not production-artifact acceptance. Candidate-specific verification is recorded
separately after publication. All asset kinds, live-harness behavior, cloud/Git
provider support, all concurrent-writer environments, Intel execution and clean-Mac
online/offline first launch are not established by these tests. Native Windows
signing does not guarantee immediate SmartScreen reputation. The repository-wide
review was risk-prioritized, not exhaustive assurance that all defects are absent.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
