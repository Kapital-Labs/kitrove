# Kitrove 0.1.0-rc.5.4

Fresh-install evaluation preview only. Use a new isolated collection and empty
destination with synthetic or disposable capabilities. This is not a stable
release, an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared: RC4.2 cannot read authored-pack collections. Binary
rollback does not roll back collection data. Do not bypass installer refusals.

RC5 stopped at validation, RC5.1 during Intel Mac notarization, and RC5.2 during
Intel Mac DMG stapling after notarization was Accepted. None produced a public
release, and all prior tags remain immutable. The old provider cause is unknown.
RC5.3 also stopped before publication at Apple ticket validation and a Windows
prerequisite download. This candidate selects Apple Silicon-only macOS binaries,
plus x86-64 Linux and Windows. Intel Mac is unsupported for this preview; older
Intel assets remain unchanged. Native signature, notarization, ticket attachment
and complete verification requirements remain mandatory. No firewall workaround
or automatic signing/notarization/attachment retry is used.

## Changes

- Exact plan/approval CLI workflows for adoption, update, apply, removal, pack
  creation, import and rollback, including stale-approval refusal.
- Locally authored packs that preserve each member's provenance.
- Opt-in versioned JSON errors for agent integrations.
- Explicit partial-fidelity reporting for omitted native-only skill fields, with
  exact native source preservation; malformed MCP activation switches are refused.
- Resumable interrupted atomic-batch rollback, iterative deep-profile validation,
  and managed instruction insertion that respects the existing region ceiling.
- Reviewed signing-process cleanup and redacted notarization receipt diagnostics;
  uncertainty still refuses cleanup success and publication.
- Apple Silicon-only macOS publication selection, distinct from historical
  archive recognition, with explicit Intel signing refusal before credentials.
- Read-only ticket validation recovery limited to confirmed connection loss on
  unchanged bytes within the original deadline; unknown failures still refuse.
- Closed native-provider diagnostics, confirmed process ownership and bounded
  Windows prerequisite transport retries preserving pinned tool verification.
- Release archive filename-identity checks, Unix transaction-lock correction and
  previously reviewed ZIP, TLS, ctutils, Tokio and crypto-bigint security updates.
- Rust 1.88 minimum for source builds.
- Narrow dependency follow-up to crypto-bigint 0.7.10 and required ctutils 0.4.6;
  all unrelated dependency versions, edges and features remain unchanged.
- Complete reviewed third-party notices, license inventory and exact attribution
  texts in both product archives, reproduced from authenticated locked sources.

The license inventory covers the complete locked dependency graph, including
build, test and other-platform dependencies; it is not a statement that every
listed package is linked into each executable.

Cloud-provider sync remains roadmap work only. Existing RC4.2 package-manager
channels and the pending RC4.2 WinGet submission are not RC5.4 distribution paths.

## Download verification before execution

Choose the exact CLI or installer archive for Apple Silicon Mac,
x86-64 Linux or x86-64 Windows from this release's assets. Mac installer DMGs
are separate containers. Adjacent SHA-256 files and the combined checksum are
integrity checks, not substitutes for provenance and native verification.

Use an independently trusted GitHub CLI and independently resolve this release's
full source commit. Compare it with the source commit recorded below; substitute
that full commit and the actual local artifact path in this command:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.4 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.4/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. The
downloaded installer cannot establish trust in its own first execution; use an
independently trusted or reviewed-source-built verifier. Do not pipe downloads
into a shell or PowerShell, remove quarantine, or disable Gatekeeper. Generated
convenience scripts are not the supported authenticated bootstrap procedure.

## Acceptance limits

Prior bounded source-built Mac/Linux skill roundtrip evidence covered adoption,
authored-pack transfer, import/apply, member updates, reverse transfer, provenance,
stale-approval and unmanaged-file refusal, removal, rollback and local-authority
exclusion. It used an isolated filesystem backend ferried between machines.

The preceding reviewed source also passed a fresh nonpublishing Apple Silicon
diagnostic: all three notarizations, ticket attachment, strict signature and
complete final verification. No connection-loss error or retry occurred. That
does not prove intermittent faults are eliminated or establish this version's
artifact acceptance.

Those results are not RC5.4 production-artifact fresh-install acceptance,
all-asset-kind, cloud/Git-provider, concurrent-writer, live-harness, Intel execution,
or clean-Mac online/offline-first-launch evidence. Cross-compilation and static
architecture checks are not Intel runtime acceptance. Native signing does not
guarantee immediate Windows SmartScreen reputation. Candidate-specific published
artifact verification and acceptance must be recorded separately; do not infer
them from publication. The repository-wide review was risk-prioritized, not an
exhaustive assurance that every defect is absent.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
