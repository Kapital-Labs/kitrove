# Kitrove 0.1.0-rc.5.7

An evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. RC5.6 and all earlier tags/assets stay immutable.
Existing RC4.2 APT/RPM packages and the separate WinGet submission are not RC5.7
distribution paths. Cloud-provider sync remains roadmap work only.

## Clearer guided setup

`kitrove init` detects an existing collection or machine-local state before asking
for a new machine name or approval to create it. A valid existing setup offers
explicit continuation into the setup menu, without re-creating state or repeating
the initial collect/connect/import action. Invalid, incomplete or in-use state stops
with inspection guidance; nothing is deleted, overwritten or repaired implicitly.

The setup menu now leads with what you want to do:

1. Add skills from this computer.
2. Choose skills to add to your AI tools.
3. Share this collection with another computer.
4. Copy selected items from another collection.
5. Finish for now.

Questions and the input marker use cyan in recognized interactive terminals.
Command output and no-write previews have separate labels and indentation; hints
are subdued and status messages retain readable text labels. `NO_COLOR`, unknown
or dumb terminals and redirected output remain plain text. Color is optional;
spacing and labels distinguish questions from results without it.

Sharing/copying asks about storage only inside those paths, with advanced Git
choices and a Not now option before opening a backend. Sharing still reviews both
upload and download changes; copying is still one-time and leaves the remote alone.
Apply, sync, execution trust and data writes retain separate exact-plan approvals.
JSON and confirmation defaults are unchanged. The existing quick collection flow
still accepts numbered selections or `all,-3,-8`; Enter previews, then one `y`
approves only the displayed ready set. Adoption does not apply or execute skills.
Credentials, machine identity, trust and deployment receipts remain local.

## Verify downloads before execution

Select the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum check integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's full
source commit. Compare it with the source commit recorded below. Substitute that
full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.7 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.7/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. A downloaded
verifier cannot establish trust in its own first execution; use an independently
trusted or reviewed-source-built verifier. Do not pipe downloads into shells,
remove quarantine, disable Gatekeeper or bypass provenance checks. Generated
convenience scripts are not the authenticated bootstrap procedure.

## Acceptance limits

Source validation, synthetic setup tests and unsigned local smokes are not
production-artifact acceptance. Candidate-specific verification is recorded
separately after publication. Every asset kind, live-harness behavior, cloud/Git
provider support, all concurrent-writer environments, Intel execution and clean-Mac
online/offline first launch are not established by these tests. Native Windows
signing does not guarantee immediate SmartScreen reputation. The repository-wide
review was risk-prioritized, not exhaustive assurance that all defects are absent.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
