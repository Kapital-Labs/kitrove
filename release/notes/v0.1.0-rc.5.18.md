# Kitrove 0.1.0-rc.5.18

Evaluation preview for Apple Silicon macOS, x86-64 Linux and x86-64 Windows.
Use isolated collections and disposable destinations. This is not stable support,
an RC4.2 migration, or a supported in-place upgrade. No rollback-compatible
predecessor is declared; binary rollback does not roll back collection data.
Intel Macs remain unsupported. Earlier tags and release assets remain unchanged.
Existing RC4.2 APT/RPM packages and the separate WinGet submission do not
distribute this preview.

## Changes since RC5.17

- Scan starts with a compact summary and short action menu. Supported, sufficiently
  sized Mac/Linux terminals accept Up/Down and Enter as well as immediate shortcuts.
  Native Windows, narrow and unrecognized terminals retain the short keyed menu.
- Unreadable folders appear under **View scan issues**, with the source location,
  explanation and next step. They are no longer counted as skills named `(missing)`.
  Actual malformed skill candidates remain visible for review. An unavailable
  folder makes the inventory incomplete; it does not prove there are no skills.
- Choose **Scan again** to repeat the same tools, scope, project boundary and
  explicit roots. The refreshed report supplies the final scan status and optional
  collection preview. No automatic rescan or background work is introduced.
- Browsing defaults to a read-only action or Back; an empty scan defaults to Quit.
  Escape/quit/EOF restore terminal input, and queued input cannot approve a later
  collection step. Initialization, fresh adoption previews, exact local script
  approval, tool placement and sync retain their separate existing approvals.
- After collecting another skill, previously added unchanged skills remain
  **Already current (managed)** instead of failing a generic planning check.
  Approving them refreshes the local receipt without rewriting their files.
- An incompatible tool selection offers **Choose different items** instead of
  ending setup. Compatible skills and scripts can be selected separately;
  incompatible items are never silently omitted, and script approval stays separate.
- Saved skill descriptions use readable quotes and single-line prose while
  keeping terminal control and formatting characters safely escaped.
- Canonical JSON/verbose report and receipt schemas, native source identity,
  root safety, capture limits, dependencies and signing workflow are unchanged.

The third-party graph is unchanged from RC5.17. The existing informational
chrono0.4.45 maintenance warning is retained without suppression or an unrelated
dependency upgrade; a fresh audit must report zero known vulnerabilities before
publication. This is not an exhaustive security assurance.

## Verify downloads before execution

Choose the exact CLI or installer archive for your platform. The Apple Silicon
installer DMG is a separate container. Adjacent SHA-256 files and the combined
checksum establish integrity, not provenance or native identity.

Use an independently trusted GitHub CLI and independently resolve this tag's
full source commit. Compare it with the source commit recorded below. Substitute
that full commit and your actual local artifact path:

```sh
gh attestation verify <downloaded-artifact> \
  --repo Kapital-Labs/kitrove \
  --signer-workflow Kapital-Labs/kitrove/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0-rc.5.18 \
  --source-digest <release-commit> \
  --signer-digest <release-commit> \
  --deny-self-hosted-runners
```

Follow the [versioned installer guide](https://github.com/Kapital-Labs/kitrove/blob/v0.1.0-rc.5.18/docs/INSTALLER.md)
for exact bundle selection, native verification and private staging. Use an
independently trusted or reviewed-source-built verifier. Do not pipe downloads
into shells, remove quarantine, disable Gatekeeper, or bypass provenance checks.

Source checks and disposable setup tests do not establish clean-Mac offline
first launch, live-harness parity, or recovery of an existing interrupted sync.
Native Windows signing does not guarantee immediate SmartScreen reputation.

Report security issues through [private vulnerability reporting](https://github.com/Kapital-Labs/kitrove/security/advisories/new),
without posting credentials or private capability content in public issues.
